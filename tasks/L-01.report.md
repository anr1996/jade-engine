# L-01 report - Workspace skeleton

## What changed

Created the Cargo workspace from an empty repository. No dependencies, no engine
code beyond doc comments and the two `main` stubs.

**Root**

- `Cargo.toml` - virtual manifest (no `[package]`), `resolver = "3"`,
  `members = ["crates/*", "apps/*"]`, `[workspace.package]` with
  `edition = "2024"` and `version = "0.1.0"`.
- `Cargo.lock` - generated by the first build; committed because the workspace
  contains binaries.
- `scripts/check.sh` - `#!/bin/sh`, `set -eu`, runs fmt check, clippy, tests in
  that order. Mode `100755`.

**Library crates** in `crates/` (12): `engine-core`, `engine-platform`,
`engine-render`, `engine-assets`, `engine-world`, `engine-physics`,
`engine-anim`, `engine-audio`, `engine-ui`, `game-data`, `game-sim`,
`game-save`.

Each has `Cargo.toml` with `name`, `version.workspace = true`,
`edition.workspace = true`, and no `[dependencies]` table; each `src/lib.rs` is a
single `//!` line naming what the crate will own.

**Binary crates** in `apps/` (2): `sandbox`, `game`. Same workspace-inherited
manifest shape, `src/main.rs` prints the crate name.

## Decisions

- **Virtual manifest over a root package.** The repo is a pure workspace shell;
  adding a root crate would have meant inventing a name and a `src/main.rs` the
  task never asked for.
- **Glob members (`crates/*`, `apps/*`) as specified.** New crates are picked up
  without editing the root manifest. The trade-off is that any stray directory
  with a `Cargo.toml` under those trees silently joins the workspace.
- **Edition and version inherited, not repeated.** Every crate uses
  `.workspace = true` for both, so a future version bump is one line in the root.
  Verified via `cargo metadata`: all 14 packages report edition `2024` and
  version `0.1.0`.
- **One-line doc comments are inferred from crate names.** L-01 fixes the crate
  names but not their responsibilities, so these lines are provisional. E.g.
  `engine-world` is "Open-world scene graph, cell streaming, and entity
  bookkeeping", `game-save` is "Save-game serialization, migration, and
  persistence". Later tasks that own a crate should treat its line as editable.
- **`/bin/sh` + `set -eu`** rather than bash. `set -e` is what provides
  "stops at the first failure"; `set -u` catches unset variables. No `pipefail`
  is needed because the script has no pipelines.
- **No `[workspace.dependencies]`, no lint table.** Nothing to share yet, and the
  task says no dependencies. `-D warnings` comes from the clippy invocation
  rather than a `[workspace.lints]` section, matching the AGENTS.md command
  exactly.
- **No `rust-toolchain.toml`.** Not requested; the environment's stable toolchain
  is used. See known gaps.

## Verification

Toolchain: `cargo 1.99.1`, `rustc 1.99.1`, `rustfmt 1.10.0-stable`,
`clippy 0.1.99`.

- `cargo build --workspace` - succeeded, all 14 packages compiled.
- `cargo fmt --all -- --check` - exit 0.
- `cargo clippy --workspace --all-targets -- -D warnings` - exit 0, no warnings.
- `cargo test --workspace` - exit 0; 0 tests across 14 unit/test targets and 12
  doc-test targets, as expected for empty crates.
- `./scripts/check.sh` - exit 0.
- `cargo run -q -p sandbox` prints `sandbox`; `cargo run -q -p game` prints
  `game`.
- `cargo metadata --no-deps` reports exactly 14 packages with uniform edition
  2024 and version 0.1.0.
- **Fail-fast behaviour tested, not assumed.** Temporarily introduced a
  misformatted line into `crates/engine-core/src/lib.rs` and ran
  `./scripts/check.sh`: exit 1, one fmt diff reported, and no clippy `Checking`
  lines - so the script stopped at the first gate instead of continuing. The file
  was then restored and the full gate re-run clean (exit 0).

## Known gaps

- **Crate ownership comments are guesses** from crate names. There is no design
  document in the repo defining responsibilities, so these may be wrong in
  detail; they are placeholders until the owning task lands.
- **No committed toolchain pin.** Edition 2024 needs rustc >= 1.85 and
  `resolver = "3"` needs Cargo >= 1.84. Builds outside this environment depend on
  whatever stable is installed. Out of scope for L-01, but a
  `rust-toolchain.toml` would make this reproducible.
- **No CI service setup** - explicitly out of scope. `scripts/check.sh` is the
  local entry point CI should eventually call.
- **Zero test coverage** - there is nothing to test yet. The clippy `-D warnings`
  and doc-comment burdens start with the first real code.
- **`[workspace.package]` has no `license`, `rust-version`, or `authors`.** Not
  requested. Worth adding before any crate is published, and `rust-version`
  would document the 1.85 floor above.
- **No `engine-core` interface requests.** Nothing was needed from `engine-core`
  for this task, so nothing is requested here.
