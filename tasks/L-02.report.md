# L-02 report — Core interfaces

## What changed

`engine-core` now provides the foundation interfaces every other crate builds
on, and `apps/sandbox` demonstrates them.

### engine-core

- `crates/engine-core/Cargo.toml` — added `bevy_ecs = "0.20.1"` and
  `glam = "0.34.3"` (resolved via `cargo add`).
- `crates/engine-core/src/stage.rs` — `Stage` enum: `Startup`, `FixedUpdate`,
  `Update`, `Render`.
- `crates/engine-core/src/time.rs` — `Time` resource: `delta: f32`,
  `elapsed: f32`.
- `crates/engine-core/src/transform.rs` — `Transform` component:
  `translation: Vec3`, `rotation: Quat`, `scale: Vec3`.
- `crates/engine-core/src/app.rs` — `App` container and `Plugin` trait.
- `crates/engine-core/src/lib.rs` — module layout and re-exports.

### apps/sandbox

- `apps/sandbox/Cargo.toml` — path dependency on `engine-core`.
- `apps/sandbox/src/main.rs` — `DemoPlugin` with a `startup` system and a
  `tick` system; `main` calls `update()` three times.

## Public API

- `Stage` (enum, derives `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`,
  `ScheduleLabel`)
  - `Startup`, `FixedUpdate`, `Update`, `Render`
- `App`
  - `new() -> App` — one empty `World`, one `Schedule` per `Stage`
  - `add_plugin(&mut self, plugin: &dyn Plugin) -> &mut Self`
  - `add_systems<M>(&mut self, stage: Stage, systems: impl IntoScheduleConfigs<ScheduleSystem, M>) -> &mut Self`
  - `insert_resource<R: Resource>(&mut self, value: R) -> &mut Self`
  - `world(&self) -> &World`
  - `world_mut(&mut self) -> &mut World`
  - `update(&mut self)` — `Startup` once, then `FixedUpdate`, `Update`, `Render`
  - `Default`
- `Plugin` (trait) — `build(&self, app: &mut App)`
- `Transform` (component)
  - `translation: Vec3`, `rotation: Quat`, `scale: Vec3`
  - `Default` = identity (`Vec3::ZERO`, `Quat::IDENTITY`, `Vec3::ONE`)
- `Time` (resource)
  - `delta: f32`, `elapsed: f32`
  - `Default` = `0.0` for both
- Re-exports
  - `glam` (the crate), `glam::{Quat, Vec3}`
  - `bevy_ecs::prelude::*`

## Decisions

- **bevy_ecs 0.20.1, glam 0.34.3.** `cargo add -p engine-core bevy_ecs glam`
  resolved the current releases, so I did not assume 0.16/0.30. The code targets
  the 0.20 schedule API.
- **`Stage` derives `ScheduleLabel`.** `bevy_ecs` 0.20's `Schedule::new`
  requires a `ScheduleLabel`, so each stage's schedule is labeled with its
  stage.
- **`add_systems` mirrors the 0.20 signature.** 0.20 replaced
  `IntoSystemConfigs` with `IntoScheduleConfigs<ScheduleSystem, M>`; the App
  method forwards to `Schedule::add_systems` with the same shape, so plain
  system functions register directly.
- **`add_plugin` takes `&dyn Plugin`.** The trait is object-safe
  (`build(&self, app: &mut App)`), which keeps the method simple and lets
  callers pass any plugin by reference.
- **Sandbox demo uses `Local<u32>` for the tick counter, not a custom derived
  resource.** See Known gaps — bevy's `Resource`/`Component` derive macros
  expand to `bevy_ecs::...` paths that only resolve when the downstream crate
  itself depends on `bevy_ecs`. The task restricts `sandbox` to a path
  dependency on `engine-core`, so the demo avoids those derive macros entirely.

## Known gaps

- **Re-exported bevy derive macros cannot be used by downstream crates that
  depend only on `engine-core`.** `#[derive(Resource)]` / `#[derive(Component)]`
  (and the other bevy derives) generate `bevy_ecs::...` paths, so a crate must
  name `bevy_ecs` (or `bevy`) in its own `Cargo.toml` for the expansion to
  compile. `engine-core` re-exports them as required, but the sandbox demo
  sidesteps them. If later tasks need downstream crates to derive
  `Resource`/`Component` through `engine-core`, that will require either
  loosening the dependency rule or engine-core providing its own derive macros.
- **`Time` is inert.** `delta` and `elapsed` are always `0.0`; task G-01 fills
  them in.
- **`Transform` is data-only.** No helpers beyond `Default`; later tasks will
  likely add transform math.
